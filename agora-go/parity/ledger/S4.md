Harness-state notes (nothing to chase, recorded for whoever re-runs S4):

* The Kotlin in-JVM caches (`ConsultationStrapiCacheByIdRepositoryImpl`, 5 min) persist across scenarios and are not cleared by the runner's Redis flush.
  A run is only reproducible from **fresh processes**: `restart-ref` AND `restart-go` before `test -tags S4` (restarting only one side leaves one side with a warm
  by-id cache and the SET of Strapi URIs differs). The variant scenarios use one consultation id each so a re-run within 5 minutes of the same process does not mix them.
* A Kotlin feedback that throws (null element in a Strapi list, NPE) leaves the user's `AgoraQueue` lock held until the JVM restarts. `S4-invalid-null-element-feedback`
  uses one user per throwing step; `restart-ref` clears the locks.
* `SELECT DISTINCT consultation_id` order feeds `filters[documentId][$in]=a&...` of the answered consultations: the order depends on the Postgres plan. Both slot
  databases are set to `plan_cache_mode = force_custom_plan` and the setup SQL of scenarios that insert answered rows runs `ANALYZE user_answered_consultation`.
* The fake Strapi clock is pinned (`strapi_now`, 2026-10-06T22:09:28Z) while the backends use the real clock: the date variants use −3 d / +8 d / +12 d offsets so the
  state (ongoing / ended) does not depend on the day the scenarios run.

## Foundation findings (nothing was modified in the foundation packages)

1. **xmljava: a null `List?` property is written as an empty element.** Jackson XML omits a null `List?`/`Collection` property (even without `NON_NULL`), `xmljava`
   writes `<goals/>`. Repro: `GET /v2/consultations/{id}?mediaType=xml` for any consultation whose latest update has `goals: null` (every view but the unanswered
   view of an ongoing consultation); `S4-known-xml-null-list` (skipped): ref lacks `<goals/>` between `<footer/>` and `<history>`. The covered XML steps are restricted to the views where
   `goals` is not null.
2. **httpx: `application/xml` request bodies** (existing C-XML-BODY in `DIVERGENCES.md`): Kotlin decodes an XML `POST` body (200), Go answers 400.
   `S4-known-xml-request-body` (skipped) is the repro on `POST .../feedback`.
3. **`LocalDateTime` has no foundation type.** `common.LocalDate` exists; the Strapi consultation DTOs need a Jackson `LocalDateTime` (string trimmed, `T` case-insensitive, trailing `Z`
   stripped, arrays of 5-7 integers, numbers refused). It lives in `internal/modules/consultation/localdatetime.go` (checked against the JVM oracle `s4LocalDateTime`); if another
   slice needs it, promote it to `internal/common`.
4. **Runner / fake Strapi limits.** (a) The Kotlin in-JVM caches survive the per-scenario reset (see Harness-state notes above); (b) the fake Strapi override cannot
   return `data: null`-like payloads that are not valid objects (`data: [null]` of the list, a string) - the corresponding scenarios were removed; (c) the fake Strapi clock is pinned.
5. **AgoraQueue** (existing B-AGORAQUEUE): two simultaneous requests of one user can both run in Kotlin; the Go queue is atomic. `S4-known-agora-queue-race` (skipped).
