## FCM: what the harness can compare

* The notification rows (`notifications` table, dbdiff `step`) and the HTTP responses are compared. The FCM requests are **not**:
  * the reference's `FirebaseWrapper` initialises only when `FIREBASE_CREDENTIALS_JSON` is set; the parity environment does not set it (`parity/env/common.env`), so on the reference every scheduled batch fails with
    `IllegalStateException: FirebaseApp with name [DEFAULT] doesn't exist` (logged by the scheduler, after the HTTP response; `ref.log`). Go fails the same batches with `ErrNotInitialized` (logged). Both sides send nothing;
  * even with credentials, the firebase-admin 9.3.0 of the reference hard-codes `https://fcm.googleapis.com` (`FirebaseMessagingClientImpl`, `MessagingBatchClient`); there is no environment switch, so the harness cannot point the reference to a fake FCM endpoint. The Go side has `FCM_ENDPOINT`, but a comparison needs the same endpoint on both sides (see "Foundation findings", 1).
* What is checked instead: the batch rules are unit-tested (300 tokens per batch, the blanks and duplicates removed, batch `i` due at now + `i` minutes, one worker, the data keys `type` and `pageArgument`) and the JVM oracle checks the texts.

## Foundation findings (nothing in the foundation packages was modified)

1. **FCM cannot be compared on the reference** (see above). Proposal for the lead (touches `parity/runner` or the parity environment, not done here): run the reference with `FIREBASE_CREDENTIALS_JSON` set to a fake service
   account (its `token_uri` pointing to a local fake) and make `fcm.googleapis.com` resolve to a local TLS fake whose CA is in the reference's truststore (`-Djavax.net.ssl.trustStore`), and set `FCM_ENDPOINT` on the Go side to the same fake. Then the batches (the JSON of `messages:send`, one per token) can be recorded on both sides as the Strapi URIs are.
2. **Spring binds a `@RequestParam` with a default value differently when the converted value is null** (`httpx`/conventions, section 3): with a `defaultValue`, Spring does not report a missing value after the conversion, so a null
   (the empty first value of several for an enum, `type=&type=HOME_QAGS`) reaches the Kotlin method, whose non-null parameter check throws a NullPointerException: HTTP 500 (`ref.log`: "Parameter specified as non-null is null: method ...notifyAllUsers, parameter type").
   `typeParam` in `handlers.go` reproduces it with a plain panic. Worth a line in CONVENTIONS section 3 (the default value suppresses the missing-value check) and a helper if another slice needs it.
3. A plain error panic (not an `httpx` error) is the Spring 500 body: no change needed (used for the NullPointerException above and for the list of a malformed row).
