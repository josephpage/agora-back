## Behaviour (all verified against the JVM)

* **Pages**: one `requestSingleType` per page (`GET <model>?pagination[pageSize]=100&populate=*`). Every Kotlin property is non-null
  (only `programme_du_mois`, `comment_ca_marche` are optional): a missing/null field, an HTTP error, malformed JSON, `data: null`,
  `STRAPI_SUSPENDED` all give HTTP 500 (not cached). Rich texts are rendered by `strapi.RichText.ToHTML()` (no `<body>`).
  `Cache-Control: max-age=300, public`. `page-questions-au-gouvernement` replaces every `{}` of `nombre_de_questions` with
  `SELECT count(*) FROM qags WHERE status = 1` (queried at every request, after Strapi: a Strapi failure answers 500 without a query).
* **News**: collection `welcome-page-news` sorted `date_de_debut:desc`; the news with the greatest `date_de_debut` <= `LocalDateTime.now(clock)`
  (first one on a tie, `maxByOrNull`); none -> `404` with no body (also on any Strapi failure, since a failed collection is empty);
  a `null` element of `data` -> NPE -> 500. A date Jackson refuses (offset, date only, ...) makes the **whole list** undecodable, hence 404.
* **Charter**: `charte-participations?...&filters[datetime_debut][$lt]=<now ISO>&sort[0]=datetime_debut:desc`, `first()` of the list:
  an empty list (also a Strapi failure) is a `NoSuchElementException` -> 500. `<body>` is added by the controller. ETag: httpx (exact path).
* **Fiches**: filters `titre` and `thematique` (`String?` params: several values are **joined with ","** by Spring, blank -> null, not trimmed),
  `etape`, `conditionParticipation`, `modaliteParticipation` (`List<String>?`: one value is split on "," and each element `String.trim()`med,
  several values are kept as they are; then Kotlin `trim()` + drop empty + empty list -> null), `anneeDeLancement`. Strapi request:
  `contains` (`$containsi`) on `titre`, `filterIn` repeated per value (no index), `sort[0]=debut:desc`. List: cached 5 minutes under
  `toCacheKey` - null filters are written `null` (so `?titre=null` shares the key of an unfiltered request, and so do `?titre=%20` etc.),
  lists are sorted (`String.compareTo`) in the key only, **empty lists are cached too** (a Strapi failure is cached for 5 minutes), a mapping
  exception is not cached. Detail: not cached, `getByIds([id])`, only the first element counts (`firstOrNull`, a `null` first element is a miss),
  a miss (also a Strapi failure) -> 404 `{"title": ...}` (`DefaultControllerAdvice`).
  `debut`/`fin` are `LocalDate`s printed `yyyy-MM-dd 00:00:00` (year > 9999 gets a `+`, BCE years are years of era).
* **Feedback**: authenticated users only (`anyRequest().authenticated()`: anonymous 401). Order: `@RequestBody` first (415/400 by httpx), then
  `getUserId()!!`. `type` is matched on `lowercase()` (`Locale.ROOT`) against `bug` / `feature` / `comment`; anything else -> `400 {}`;
  non-String JSON scalars are coerced to String (`1` -> `"1"` -> unknown type -> `400 {}`), `null`/missing `type`/`description` -> Spring 400;
  `deviceInfo` is optional but each of its three fields is required. Insert into `app_feedbacks` (random UUID, `created_date` with millisecond
  precision, `type` stored lower case, device columns NULL when `deviceInfo` is absent); a database error (NUL character, value > 255 chars in
  a device column) is an uncaught exception -> 500, nothing stored. `200 {}` on success. Kotlin does a SELECT (merge) before the INSERT: Go
  only inserts.
* **java.time** (`jtime.go`, verified by fuzzing ~6000 strings + the JSON number/array/object forms against the JVM): `LocalDate` accepts
  `ISO_LOCAL_DATE`, the `T` form (`ISO_LOCAL_DATE_TIME`, upper case `T` only, trailing `Z` dropped first, date part kept), JSON integers as
  **epoch days**, `[y,m,d]`; `LocalDateTime` accepts `ISO_LOCAL_DATE_TIME` (case-insensitive `T`, `.` alone allowed, 0-9 fraction digits,
  trailing `Z` dropped only when the text has a `T` at index 10), `[y,m,d,h,mi(,s(,n))]`; everything else (offsets, empty string, numbers,
  objects, booleans, `null`) fails.

## Foundation findings (nothing under `internal/{httpx,jsonjava,xmljava,cache,javacompat,...}` was modified)

Every item has a scenario in `S9_known_foundation_diffs.yaml` unless said otherwise. "Workaround" = what S9 does locally.

1. **httpx - `Accept` header of a 415.** `POST /feedback` with `Content-Type: text/plain` (also none, form, multipart, octet-stream, text/html).
   Reference: `Accept: application/xml;charset=UTF-8, text/xml;charset=UTF-8, application/json, application/*+xml;charset=UTF-8, application/*+json`;
   httpx (`acceptForBodies`): `application/json, application/*+json, application/xml, text/xml, application/*+xml`. Scenario
   `s9-feedback-content-types-unsupported`.
2. **httpx - wildcard Content-Type.** `Content-Type: */*` or `application/*` on `POST /feedback`: reference 500 (`{"status":500,...}`, the
   `IllegalArgumentException` of `MediaType`), httpx 415.
3. **httpx - status >= 400 chosen by the handler + failed negotiation.** `GET /fiches_inventaire/zzz?mediaType=foo` (404 by `DefaultControllerAdvice`)
   and `POST /feedback?mediaType=foo` with an unknown type (`ResponseEntity.badRequest().body(Unit)`): reference keeps the handler's status
   (404 / 400) with an **empty body** and no `Content-Type`/`Accept`; httpx answers 406 + `Accept: application/xml, application/json`. For a 2xx
   status the reference does answer 406 (verified on every route). Workaround: `mediaTypeUnacceptable` + `httpx.Empty(status)` in
   `notFoundAdvice` / `feedbackHandler`. Every route that raises an `AdviceError` or answers a 4xx entity with a body has the same issue.
   (F1 of S0 - the handler headers kept on a 406 - is fixed in httpx: the S0 `cacheControl` workaround is not needed, S9 adds `Cache-Control`
   unconditionally and the `?mediaType=foo` scenarios pass.)
4. **xmljava - root element of a declared `List<T>`.** `GET /fiches_inventaire?mediaType=xml`: reference `<List><item>...</item></List>` (and `<List/>`),
   `xmljava.Marshal` of a slice gives `<ArrayList>` (Spring writes the declared generic type). The oracle function `xmlSerialize` writes the value,
   so it shows `ArrayList` too; the live reference is the authority. Workaround: `FicheInventaireListJSON` with `JavaName() == "List"`. Every
   `ResponseEntity<List<...>>` route needs the same.
5. **xmljava - control character in XML text.** `titre` = `a\u0000b` on `GET /content/page-site-vitrine-question-au-gouvernement?mediaType=xml`: reference
   `200`, chunked body `<SiteVitrineQuestionAuGouvernementJson><titre>a</titre></SiteVitrineQuestionAuGouvernementJson><Map><timestamp>...</timestamp><status>200</status><error>OK</error><path>...</path></Map>`
   (the Woodstox failure happens after the headers are committed, the error dispatch appends its body; Go's HTTP client sees an unexpected EOF);
   Go answers a clean 500 error body. Scenario `s9-known-content-xml-control-char`.
6. **httpx - repeated query parameters.** `Ctx.Param` / `RequiredParam` / `OptionalParam` return the first value; Spring binds a `String` parameter
   given twice (`?titre=a&titre=b`) to `"a,b"` (`ArrayToStringConverter`). `Ctx.ParamList` trims single-value elements with `strings.TrimSpace`
   (also U+0085, U+00A0) where Spring uses `String.trim()` (chars <= U+0020). Workaround: `queryValues` / `stringParam` / `listParam` in `fiche.go`
   (they re-parse `RawQuery` like `Ctx` does). Verified by the filter scenarios.
7. **httpx / javacompat - invalid UTF-8 in the query string.** `GET /fiches_inventaire?titre=%E9`: Tomcat decodes the bad byte to U+FFFD, so Kotlin asks Strapi for
   `%EF%BF%BD`; Go keeps the raw byte and `javacompat.URLEncode` writes `?` (`%3F`) for every `utf8.RuneError`, so even a genuine `%EF%BF%BD` becomes `%3F`
   (a lone surrogate and a real U+FFFD are the same Go rune). Partial workaround `replaceInvalidUTF8` (one U+FFFD per invalid byte, Java gives one per
   malformed sequence: differs for truncated multi-byte sequences). The `URLEncode` part cannot be worked around locally:
   `s9-known-fiches-list-fffd-*` (6 scenarios).
8. **httpx - invalid characters in the path.** `GET /fiches_inventaire/%FF` and `/%ED%A0%80` (invalid UTF-8, Tomcat: `400`, `text/html;charset=utf-8`,
   `Content-Language: en`, no Spring headers) and `/a%0Ab` (decoded control character: Spring Security's firewall `400` JSON error): Go reaches the handler
   (404). Scenarios `s9-known-fiches-detail-*`.
9. **jsonjava / httpx - request body decoding (the areas being rewritten by the lead)**, `POST /feedback`:
   * UTF-8 BOM before the JSON: reference `200` (row inserted), Go `400` (`s9-feedback-encoding-bom`);
   * `Content-Type: application/json;charset=ISO-8859-1`: the reference decodes the body with that charset (`é` sent as UTF-8 is stored as `Ã©`;
     Spring only lets Jackson auto-detect the UTF-8/16/32 charsets), Go decodes UTF-8; `charset=nope`: reference `415`, Go `200`
     (`s9-feedback-encoding-bom`, `s9-feedback-content-types-charset`). `charset=UTF-16` on a UTF-8 body behaves the same on both sides
     (kept in the passing `s9-feedback-content-types`: a regression guard for the decoder rewrite);
   * a lone surrogate escape (`"a\ud800b"`): the reference stores `a?b` (JDBC), Go stores `a<U+FFFD>b` (Go strings cannot hold a lone surrogate)
     (`s9-feedback-lone-surrogate`);
   * invalid UTF-8 bytes in the body cannot be written in the scenario YAML: not covered here.
10. **httpx - XML request bodies** (known C-XML-BODY): `application/xml`, `text/xml`, `application/vnd.x+xml` bodies are read by the reference
    (row inserted, `200`), refused by Go (`400`). Scenario `s9-known-feedback-xml-body`.
11. **fake Strapi** (parity harness, not a product issue): an override cannot contain a `null` element of `data` (HTTP 400), so "null element" cases
    (`NullPointerException` -> 500, `firstOrNull` -> miss) are covered by the unit tests and the oracle pipelines only.
