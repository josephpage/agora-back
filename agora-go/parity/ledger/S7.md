## Reproduced Kotlin quirks (checked on the reference through the scenarios)

* **List**: OPEN QaGs only, not in `moderatus_locked_qags`, oldest first, 100 at most. A NULL `user_id`, `title`, `description`, `username` or `post_date` on one of them makes the WHOLE list a 500 (non-null Kotlin fields, `QagInfo` constructor): `S7-new-qags-null-*`, both sides identical.
* **Lock** (`ack_qags`): the ids are compared as written (`lockedQagIds.distinct()`, then `getQagInfo`), a lenient UUID (`0-0-4000-8000-23`, upper case) is found and stored canonically, the confirmation echoes the id as sent; locked, not OPEN, unknown, not a UUID = `NOTFOUND`; a wrong password echoes every id with `ERROR`. Tabs around ids are trimmed (`S7-ack-qags-separators`).
* **Moderation** (`result_qag`): login first, then the exact `OK` / `NOK` (`" OK"` and `"ok"` are 400, even for an unknown QaG). Accepting an OPEN QaG notifies with a RANDOM accepted message (`Set.random()`), rejecting it with the fixed rejection message; a MODERATED_ACCEPTED QaG rejected gets the rejection, a MODERATED_REJECTED QaG accepted gets "Bonne nouvelle !" (fixed); accepted again or rejected again = no notification. The lock of an OPEN QaG is removed by any moderation of it. A `qag_updates` row is written by every successful moderation, the motif is stored even when null (`qags.motif_id`).
* **`kill`**: `toIntOrNull` of the Kotlin string (`"+1"` = 1, Unicode digits such as `"١"` = 1, `" 1"` = 0, `"1.0"` = 0); `should_delete_flag` only for NOK with 1.
* **Repeated `motif`** (String parameter) is joined with `,` (`a,b`); repeated `status` of the admin route = the first value (fixed in this slice); `result_qag` `status` is a String: `OK` + `NOK` = `OK,NOK` = 400.
* **Admin status**: the value is trimmed (`"  ARCHIVED  "`, `"\tOPEN\t"`), the id is looked up as a UUID (upper case and lenient spellings found, the update uses the canonical id), an unknown or deleted QaG = 404 with an empty body, `ARCHIVED` / `SELECTED_FOR_RESPONSE` set without any notification or `qag_updates` row.
* **Corrupt status** (a row whose status is not one of the five, e.g. 99): the list ignores it, moderation, lock and admin status answer 500 (`IllegalArgumentException: Invalid QaG status`).
* **Parallel locks**: the Kotlin read-then-write is not atomic (two simultaneous locks of one id can both succeed); not reproduced, not in the scenarios (non-deterministic).

Notes on the harness:

* **Login tokens.** The Moderatus `password` is the `LoginTokenGenerator` token of a user: AES/ECB/PKCS5 of `{"userId":...}` with the secret of `parity/env/common.env`. It is deterministic (no expiry), so the tokens of the seeded users are written literally in `gen/s7/helpers.py` (`TOKEN`), built with `auth.LoginTokens.Build(seed id)`; the reference accepts them (UserModerator and UserAdmin have the level that grants `MODERATE_QAG`).
* **Runner DB diff and random notifications.** The accepted notification of an OPEN QaG is drawn with `Set.random()` on the Kotlin side (and `rand` on the Go side): its title and message cannot match between the two databases. The scenarios that accept an OPEN QaG therefore use `dbdiff: none` and check the effects over HTTP (status in the details, the list, the lock). Every other moderation writes a fixed notification and is compared by the DB diff (`qags`, `qag_updates`, `moderatus_locked_qags`, `notifications`).
* **Per-scenario reseed**: the runner reseeds both databases before each scenario; `setup.sql` uses literal ids (`{{seed.X}}` is not expanded there). The generated QaGs use the id ranges `00000000-0000-4000-8100-*` (lists and locks) and `…-8300-*` (special rows).
* **Lists and caches**: the moderation and admin scenarios call the latest list after `sleepMs: 5300` (both sides serve a list at most 5 s old); the Moderatus lists are read in full each time.

## Foundation findings (nothing under `internal/{httpx,jsonjava,xmljava,cache,store,strapi,common,fcm,auth,config,javacompat,domain,app}` or `parity/runner` was modified)

1. **F-XML-ESC (`internal/xmljava`, `appendEscapedText` / `appendEscapedAttr`)**. Woodstox writes these code points as lowercase references, `xmljava` writes them raw: in element TEXT U+007F to U+009F, U+FFFE, U+FFFF (`&#x7f;`, `&#x85;`, `&#xfffe;`); in ATTRIBUTE values U+FFFE and U+FFFF only (U+007F..U+009F are raw in both). Minimal repro: `xmljava.Marshal(ModeratusQagListErrorXML{ErrorMessage: "a\x7fb"})` gives `<error>a\x7fb</error>`, Java `<error>a&#x7f;b</error>`; `GET /moderatus/ack_qags?password=abc&mediaType=xml&content_id=a%EF%BF%BEb` gives `content_id="a￿b"`, the reference `content_id="a&#xffff;b"` (scenario `S7-known-foundation-xml-escape-attribute-nonchar`). The S7 routes reach the attribute case anonymously; the text case is not reachable from S7 but is in the other XML routes. Oracle: `TestOracleXMLEscapeFoundation` (`PARITY_FOUNDATION_XML_ESC=1`).
2. **F-XML-CTRL (`internal/xmljava`, `MarshalChecked`)**. It refuses every U+0000..U+001F (but TAB, LF, CR) anywhere in the output, including inside CDATA, where Woodstox writes them raw: the reference answers 200 with an invalid XML 1.0 document. Repro: a QaG whose `username` contains U+0001 in `GET /moderatus/new_qags?...&mediaType=xml` (200 on the reference, 500 in Go; `S7-known-foundation-xml-cdata-control-username`). Oracle: `TestOracleXMLCDATAControlFoundation` (`PARITY_FOUNDATION_XML_CTRL=1`).
3. **F-CDATA-END (`internal/xmljava` marker + httpx streaming)**. A CDATA section containing `]]>` makes Woodstox fail while streaming: the reference has already sent its 200 headers and the first bytes, then appends the Spring error map and ends the chunked response without its terminator (curl exit 18). `xmljava` writes a marker byte that makes `MarshalChecked` fail, so httpx answers a clean 500. Reachable by any user who can ask a QaG: `POST /qags` with `title: "x ]]> y"` is stored identically on both sides (`>` survives the sanitizer: `htmlUnescape` restores it), then `GET /moderatus/new_qags?...` breaks on the reference (`S7-known-foundation-cdata-end-marker`). Not fixable in S7 (it needs a partial-body writer in httpx); see the open questions.
4. **C-XML-CONTROL-CHAR (register) — refined.** For an attribute or text value, the reference cuts the body (curl exit 18) with the status of the handler: `GET /moderatus/ack_qags?password=abc&mediaType=xml&content_id=a%01b` = **401 truncated** on the reference, **500 clean** in Go (scenario `S7-known-c-xml-control-char-content-id`). The register says "200 with a truncated XML" and "only QaG titles, which do not contain these characters": the anonymous `content_id` echo reaches it, so the reachability sentence must change.
5. **Enum request parameters (`httpx.RequiredParam`)**. `RequiredParam` joins repeated values with `,` (String semantics). A non-String `@RequestParam` (here `QagStatus`) takes the FIRST value in Spring. Repro: `PUT /admin/qags/{id}/status?status=OPEN&status=ARCHIVED` = 200 `OPEN` on the reference (400 with the join). S7 reads `c.Param` in that one handler; a helper such as `RequiredParamFirst` (or a note in CONVENTIONS §3) would avoid the trap elsewhere (S2 `DELETE`? S4 enum parameters should be checked).

### Porting notes

* **Porting trap: non-breaking spaces.** The Kotlin notification texts use U+00A0 before `!` and `?` (French typography, `"Bonne nouvelle !"`, `"10h ?"`). Go had regular spaces; found by the JVM oracle (`TestOracleNotificationMessages`) and fixed. Other slices should grep their Kotlin literals for `\xc2\xa0` when porting texts.
* **Random draws**: `Set.random()` (accepted notification) and `List.random()` (weekly selection) are uniform in both; Go keeps the Kotlin `setOf` declaration order and draws with `rand`; the sequences differ, as they do between two runs of the reference.

## Open questions for the lead

1. **F-CDATA-END** (`]]>` in a QaG title, description or username): the reference corrupts the moderation list for everyone while such a QaG is open (200 with a cut document, unterminated chunked response), Go answers a clean 500 for the same route. Is "fails more cleanly" class B for the product owner (the Kotlin body is not a valid document), or must httpx reproduce the partial stream? The root fix belongs to the storage: the Kotlin sanitizer keeps `>` (`htmlUnescape` after the OWASP policy).
2. **F-XML-ESC and F-XML-CTRL** are in `internal/xmljava` (foundation owner): suggested fixes are escaping U+007F..U+009F, U+FFFE, U+FFFF in text and U+FFFE, U+FFFF in attributes as `&#x<lowercase>;`, and not refusing control characters inside CDATA. Once fixed: `PARITY_FOUNDATION_XML_ESC=1`, `PARITY_FOUNDATION_XML_CTRL=1` for the oracle tests and un-skip the three scenarios (`S7_known_divergences.yaml`). The other slices' XML routes may be affected by the same two findings.
3. **Random accepted notification in the DB diff**: the runner cannot ignore one column. Options: a runner feature to ignore `notifications.title/description` for a step (then the OPEN accept scenarios could compare the rest of the database), or keep `dbdiff: none` (current choice).
