## For S6 (consultation responses): exactly ONE call, `InsertUserAnsweredConsultation`

After a user's answer, Kotlin's `InsertReponseConsultationUseCase` calls `consultationAnsweredPaginatedListCacheRepository.clearCache(userId)`.
In Go the ONE call is **`consultation.Get(a).Answered.InsertUserAnsweredConsultation(ctx, answered.UserAnswered{UserID, ConsultationID})`** (the insert S6 makes anyway, at the same place
as Kotlin: after the response rows are inserted; do NOT add a separate eviction call): after the commit it runs the hooks registered by `consultationlist.Get(a)`, which evict
the user's answered pages on every Go instance and, in coexistence mode, the Kotlin keys. `consultationlist.Get(a)` is built by `all.Routes` (`consultationlist.Routes`), so the hook is
registered in every web process. Besides that insert, S6 makes the call S4 already documented for another cache: `consultation.Get(a).EvictHasAnswered(ctx, consultationID, userID)`
(what Kotlin evicts for "has answered"). If S6 ever changes what a user answered **without** `InsertUserAnsweredConsultation` (a deletion, a direct SQL), call
`consultationlist.Get(a).EvictAnswered(ctx, userID)`.

## For S7 / S10 (daily task, admin)

`ConsultationCacheClearUseCase.clearConsultationCaches` also empties the finished pages: call **`consultationlist.Get(a).ClearConsultationCaches(ctx)`** (it builds the module, so the
hook that clears `consultationsFinishedPaginated` is registered even in the cron process, which never builds the routes) instead of `consultation.Get(a).ClearConsultationCaches(ctx)`.
The admin `POST /admin/cache/clear` (FLUSHDB) is handled by the cache foundation (epoch watcher clears every L1).

## Foundation findings

No foundation package was modified and no foundation change is required.

1. `cache.DeleteKotlinPattern` walks the whole keyspace with SCAN (what the Kotlin `KEYS` did): it is only called in coexistence mode, once per answer (`EvictAnswered`) and once per daily clearing. If the
   Kotlin Redis is big, a per-user explicit key list would be cheaper, but the page numbers of a user are not bounded by anything the Go side knows.
2. S4 `consultation.Service.OnClearConsultationCaches` appends to a slice without a lock and `ClearConsultationCaches` reads it: it is safe because `consultationlist.Get(a)` registers during start-up (`all.Routes`),
   before any request or task; a late registration would race. (Not changed.)
3. Harness: see "Harness notes" above (the fake Strapi refuses a `null` element in an override; the eviction after an answer cannot be a scenario until S6 exists).
