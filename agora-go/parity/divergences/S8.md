## Kotlin behaviours reproduced on purpose (class A, found with the scenarios)

* The list of a user is cached for 5 minutes and no write evicts it: a notification sent after the first read of the list is not in the list until the entry expires (`S8-paginated-after-writes-stale`).
* A row the mapper cannot build (NULL title / description / type / date) is an exception for the whole list, on every page, including the pages that do not contain it; the list is cached before the exception, so the next read fails from the cache. A `type` that Hibernate cannot read (`'9'`, `''`) fails the load: nothing is cached (`S8-malformed-*`). Type spellings are read like `getByte()` (`' 1 '`, `'1.0'`, `'+3'`, `'5.99'`, Arabic digits) (`S8-malformed-type-spellings`).
* An unknown or non-UUID subject of the JWT is a 401 (the filter rejects it, `S8-paginated-auth`); a banned user reads his own list (200).
* `notifyAllUsers` has a `type` default that is not a constant: the parameter is required in practice (absent → 400), `type=` → 400, `type=&type=HOME_QAGS` (an empty first value of several) → 500, a NullPointerException of the non-null check of the method (the default value stops Spring from reporting the missing value after the conversion). The department route behaves the same (`S8-department-params`: 500 with a valid or an unknown code, the parameters are bound before the code is checked).
* Repeated String parameters are joined with `,` (`title=a&title=b` → `a,b`); a repeated `type` uses its first value.
* The page number: `toIntOrNull` (`+1`, Arabic digits, `00001` are accepted; `1.5`, `1e1`, `0x1`, ` 1` are 400), a page 0 or negative is a 400 without a read, the page right after the last one is an empty 200, the pages after that are 400. The int arithmetic wraps: `(page − 1) × 5` negative is an IndexOutOfBoundsException (500) (`S8-paginated-page-values`, `S8-paginated-page-boundaries`).
* A user without an FCM token (`''`) is a 400 for `notifyUser` (`Veuillez renseigner un FcmToken.`), a banned user and a user sharing a token with others are notified; the deadline and the department routes notify one user per FCM token (the most recent account) and the department routes add a user living AND interested twice (`S8-notify-user-fcm-token`, `S8-consultation-deadline-all`, `S8-department-codes`).
* A notification to the answerers of a consultation goes once to each user who answered (a duplicate `user_answered_consultation` row does not duplicate it), banned users included (`S8-consultation-update-all`, consultation 4 has a duplicate row).
* `notifyUsersInDepartement` checks the code after the parameters: a bad code is a 400 with no write; an unknown consultation is a 404 with the advice body (`S8-consultation-unknown`).
