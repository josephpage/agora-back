# S7 divergences (moderation and QaG lifecycle)

The 53 scenarios of `-tags S7` are at 0 diff (class A). The differences below are the ones that remain; each one is either a
class B item (allowed), a class N item (not visible to HTTP clients) or a class C item that needs a decision by the lead
(most of them need a change in the foundation packages, which this slice must not make). The four skipped scenarios of
`S7_known_divergences.yaml` reproduce the C items over HTTP; each one fails when it is unskipped.

| id | class | Kotlin | Go | observable effect |
|---|---|---|---|---|
| B-MODLOCK | B | The lock cache `ModeratusQagLock` is never filled: `addLockedQagIds` / `removeLockedQagId` only put a value when one exists, so every `getLockedQagIds` reads `moderatus_locked_qags` in full | No cache: the table is read at each call | none: both read the table every time (the cache never serves) |

## Kotlin behaviours that look like divergences but are reproduced on purpose

* `kill`: `toIntOrNull` (`"+1"` = 1, Unicode digits = their value, `" 1"` = 0, `"1.0"` = 0); `shouldDelete` only for NOK.
* `status` of `result_qag` is a String: `OK` and `NOK` together = `OK,NOK` = 400 `Status invalide` (before any QaG lookup); `" OK"` is 400.
* The login is checked before the parameters of the moderation (401 for a wrong password whatever the `status`).
* The moderation list ignores locked QaGs and is ordered oldest first; a NULL column on an OPEN QaG is a 500 for the whole list (both sides).
* A row with an unknown status (99) is a 500 on moderation, lock and admin status (`IllegalArgumentException`), and ignored by the list.
