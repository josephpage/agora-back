## Kotlin behaviours reproduced on purpose (found with the scenarios)

* **Answer submission**, in this order: the body is bound first (400 / 415 before anything else), then the rate limit (an anonymous request is a 401 before; an unreadable body does not count; every other request of an IP counts, whatever its outcome), then the queue, then validation, then the insert.
* **Validation** (`ResponseQuestionValidator`): no question answered twice; every answer must match a question of the consultation (first one with that id) and the validator of its type: unique / conditional = exactly one choice id, multiple = no duplicate and at most `maxChoices` (so 0 allowed, and `-1` makes even an empty list invalid), open = text of at most `OPEN_QUESTION_MAX_TEXT_LENGTH` (400) UTF-16 units, any other text of at most 200 units; **a chapter has no validator** (any answer is accepted and stored); choice ids are **not** checked against the choices of the question; an open question accepts choice ids (one row each). An unknown (or Strapi-unreachable) consultation has no question: only `responses: []` is valid, and it is **accepted** (a `user_answered_consultation` row is written for an id that does not exist).
* **Insert**: a consultation that ended (`endDate` strictly before now) or that the user already answered is a 400 (`{}`); an unknown or unpublished consultation has no end date and is answerable (the questions are read with the unpublished ones, the finish check with the published ones). For each question of the consultation, in its order: the answer, else a "not applicable" answer (`11111111-1111-1111-1111-111111111111`) if the question has choices (unique, multiple, conditional); an open question or a chapter without answer has no row. A text is sanitized (`ContentSanitizer`) and cut to 400 (open question) or 200 units; an empty text is not sanitized. One row per choice id, the text repeated; no choice id (or an empty list): one row with `choice_id` NULL.
* `responses: [null]` or a `null` choice id: Jackson keeps the `null` in a `List<String>`. `responses: [null]` is a NullPointerException in the mapper (500); a `null` choice id is stored as a row without choice (a unique question accepts `[null]`, two `null`s are a duplicate for a multiple one).
* The answer is `{"askDemographicInfo": true|false}` (S1 `AskForDemographicInfo`, after the insert; an exception there is a 500 after the rows were written).
* **Results**: the denominator of a choice is the number of participants minus the "not applicable" answers of that question (only when there is at least one participant); `x / 0` is `Infinity` (`roundToInt` = `Int.MAX_VALUE`), `0 / 0` is 0, a denominator can be negative; the "seen ratio" is disabled (always 100); the aggregated table wins as soon as it has one row for the consultation (its rows for one choice are summed), else the live rows are counted; a NULL question / choice id in the aggregated table is a 500; unique **and conditional** questions share `resultsUniqueChoice`; a unique or multiple question gets a last choice "Pas de réponse" (zero UUID) which counts the skipped answers; a question with no choice is left out, an open question is only listed.
* **TSV**: one block per attribute, the keys sorted by ordinal with the null key (`N/A`) last, the percentages formatted with `NumberFormat` (4 fraction digits, grouping, HALF_EVEN on the digits of `Double.toString`, including the JDK's `5.0E-5` tie quirk); the demographic ratios are over the participants of the **whole** consultation having that value (`Infinity` -> `∞%` when nobody has it; a choice can show more than 100 %); two profile values that map to the null key replace each other in the order PostgreSQL returns the groups (the same SQL text, so the same order on both sides).
