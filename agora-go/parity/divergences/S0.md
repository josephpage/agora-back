# Slice S0 - divergences

No class C divergence. Everything below is class A (same observable bytes) or B (fresher / cheaper), listed for transparency.

| id | class | Kotlin | Go | observable effect |
|---|---|---|---|---|
| S0-1 | A | `thematiqueCache`, `themeHebdoCache` in Redis (shared by instances) | process L1 (same TTL 1 h / 5 min, same "only when non-empty" rules), FLUSHDB-aware | none: responses identical; each Go instance loads Strapi once per TTL instead of one Kotlin instance per TTL |
| S0-2 | B | `THEME_HEBDO_CACHE_ENABLED=false`: Strapi called at every `/theme_hebdo` (and every weekly-task / trending lookup) | the list is shared for `AGORA_MICROCACHE_TTL` (default 5 s, never when empty or when the mapper fails) | a change in Strapi shows up at most 5 s later (the response itself is already `max-age=10`) |
| S0-3 | A | `getThematique(id)`: one list scan, and one Strapi call per lookup while the list is empty | `ByID`: map lookup on the cached list (first match kept, same log line when absent); while the list is empty Strapi is still called per lookup | none (fewer CPU cycles) |
| S0-4 | A | one Strapi call per concurrent miss | concurrent misses share one load (singleflight, request cancellation does not abort it) | none |
| S0-5 | A | `String.uppercase()` on JDK 17 (Unicode 13) | `x/text/cases` full case mapping, with the Unicode 14+ lower case letters left unchanged | none (verified for every code point) |

Behaviours that look like divergences but are the Kotlin ones (kept on purpose): a Strapi date that `OffsetDateTime.parse`
rejects makes every `/theme_hebdo` answer 500 (also when the bad date is in a past theme); an empty/failed Strapi answer
is never cached and is retried at every call; `avatarUrl` is `null` for a Strapi theme without photo; months are
compared without the year when generating the periode.

Differences that come from the foundations and not from S0 are in `parity/ledger/S0.md` ("Foundation requests").
